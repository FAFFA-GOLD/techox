## プロダクト概要

- **名前**: TECHOox（テチョクス）。旧称 Ledger。赤字の毒を出す家計の手帖
- **いま**: 開発者自身が使いながら改善する個人用家計簿（再スタートの実践道具）
- **目的（コア）**: 給与サイクルで先々のキャッシュアウトを把握する／日々の予算を日常化する
- **将来**: 同じ境遇の人や、遊びながら人生設計できる家計・習慣アプリとして製品化を視野
- **技術**: Next.js（App Router）+ TypeScript + Tailwind + Supabase（専用プロジェクト）
- **公開予定**: Web（レスポンシブ）。Vercel 想定
- **フォント**: Noto Sans JP（ゴシック）
- **チャート**: Recharts

## データベース（Supabase）

ブログ用とは**別プロジェクト**。無料枠の容量逼迫を避けるため同居しない。

マイグレーション（SQL Editor で順に実行）:

1. `supabase/migrations/001_initial.sql` — categories / transactions / recurring_rules / balance_snapshots + RLS

## 中核コンセプト: 給与期

カレンダー月ではなく **給料日 〜 次の給料日前日** を1期間とする。

例（給料＝毎月末）:

| 期間 | 日付 | 期末の意味 |
|------|------|------------|
| 6月給与期 | 6/30 〜 7/30 | **7/30・次の給料前**の残高 |
| 7月給与期 | 7/31 〜 8/30 | 7/31給料込み＋その後の支出後の残高 |

- 給料 120,000 は **次期の開始日**に入る（6月給与期の期末には足さない）
- 設定画面で `last_day`（毎月末）または固定日

## 「予定 → 実額確定」の共通ルール

対象: 定期 / カード / ローン

1. マスタに**予定額**を登録 → 各支払日に「予定」として自動展開
2. 各月で **実額を確定** → 確定額で上書き（編集可）
3. 確定を削除 → その月は再び予定に戻る
4. 将来ビュー・給与期の集計は、確定済みなら確定額、未確定なら予定額

### 定期（給与・保険料など）

- 明細画面に予定が表示される
- 「実額を確定」で transactions に登録（`recurring_rule_id` 紐づけ）
- 日は 1〜31（無い日は月末）。「毎月月末」チェックあり

### クレジットカード

- 締め日・引落日・引落月オフセット＋**予定の一回払い／分割**
- 利用明細の自動集計はしない（引落額ベース）
- スケジュール一覧は**当月以降**（過去3ヶ月遡及はやめた）
- 確定後も編集可

### ローン

- 予定の返済＋利息で毎月展開
- `loan_payments` で月ごと実額確定（004 の実行が必要）

## 給与期 CSV 出力

- 給与期ダッシュボードの「CSV出力」→ `/api/export/period?period=yyyy-MM`
- 画面と同じフル台帳（明細・定期予定・カード・ローン）を1行1明細
- 既定エンコーディング: **Shift_JIS**（日本語 Excel 向け）。`?encoding=utf8` で UTF-8 BOM

## 日々の支出（カレンダー月）

給与期とは別に、**カレンダー月**で小遣い・日常支出を管理する（`/calendar`）。

- 用途カテゴリ初期値: 家族 / 昼食 / 日用 / その他（共通枠） / 交通費 18,860
- 小遣い予算: **〜2026-07** は作成時のおまけ固定（家族35,000・昼食15,000・日用10,000）。**2026-08〜** は DB の月予算（初期: 家族35,000・昼食19,000・日用10,000）を「月予算の調整」で編集
- 「その他」は独自予算なし。家族＋昼食＋日用の合計枠から減算。画面に「小遣い残り」も表示
- 会社都合の休日を日付単位で設定可。昼食の一日上限 = 残額 ÷（月の平日 − 会社休日）（切捨て）
- 1日に複数回入力可。各日セルに当日合計、右パネルで件数・編集・削除
- 用途ごと **残り = 月予算 − 当月使用額**（マイナス＝超過も表示）。交通費は独立予算
- 月の合計支出も表示（**交通費は合計から除外**し、横に交通費額を表示）
- テーブル: `daily_spend_categories` / `daily_spend_entries` / `daily_spend_holidays`（005〜007）
- **月次出力**: CSV（集計＋明細）と PDF「日常生活費支出明細書」
  - PDF は法的提出想定: **交通費込み総額**＋「除く／交通費／含む」の内訳
  - 画面の月合計は交通費除外のまま（運用しやすさ優先）
- **用途別一覧**タブ: 用途フィルタ・一括削除・用途一括変更
- **比較月**（`?compare=`）: 用途別の月比較グラフ（2026-08〜想定）

### 日々グラフ・ペースアラート

- 用途別棒 / ドーナツ / 日ごとカテゴリ色積み上げ＋予算残高線＋均等消化目安線
- ペース差 `gap = 実残高 − 目安残高` が負なら注意/警戒（閾値は HANDOFF 参照）
- カレンダー日付セルに **注意/警戒バッジ**（当月の平日のみ）

## 残高の運用

- **登録残高**を日付つきで日々更新（同じ日は上書き）
- 給与期最終日（次給料の前日）の残高で銀行と突合
- 給料日: 前日残高 ＋ 給料 ≒ 銀行残高

### 期末予測残高の計算（重要・修正済み）

```
最新の登録残高（例: 7/23）
＋ その翌日以降〜期末までの収支（確定額優先、未確定は予定）
＝ 期末予測残高
```

- 期間開始時点の古い起点だけを使うと、既に残高に含まれた支出を二重に引いてしまう（バグだった → 修正済）
- 例: 7/23 に 244,338、以降が PayPay・楽天のみなら  
  `244,338 − 84,102 − 11,873 = 148,363`

画面では各数値の下に**内訳行＋合計式**を表示。確定後は確定額が内訳に反映。未確定は「予定」ラベル。

## 給与期グラフ・アラート

- 収入/支出構成棒、日別収支＋累積、初日内訳注記
- 目安ペース線: 収入 − **貯金目安 14,000円/期** を均等消化した場合の累積
- アラート: 順調 / 注意 / 警戒（期末見込み・目安との差）。詳細閾値は HANDOFF

## 運用上の注意（合意済み）

- ブログ用 Supabase は容量が逼迫気味 → 家計簿は専用プロジェクト、ブログ側は近々 Pro 検討
- Free のまま容量だけ足す課金はない（Pro 一択）
- カード予定一覧は当月から（4月など過去月の予定は出さない）
- 006 未適用だと日々用途が重複し金額が異常になることがある
